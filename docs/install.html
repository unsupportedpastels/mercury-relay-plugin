Install the Mercury Relay plugin

Opening Hermes Desktop…

Open in Hermes Desktop

Hermes shows a confirmation dialog before anything is installed. It detects both halves of this plugin (the gateway half and the Hermes Desktop half) and installs the gateway half on whichever gateway is active in Hermes Desktop, local or remote.

Before you click Install in the dialog

  • git must be on PATH on the machine that runs the gateway. Hermes clones this repository with git and does not bundle it. Without git the gateway half fails with git is not installed or not in PATH while the desktop half still installs.
  • Leave both checkboxes and the Enable switch on. The dialog can install the desktop half alone, which gives you the relay page but no relay.
  • Read the dialog before closing it. If the gateway half fails, the error is shown in red inside the dialog while a green "Desktop plugin installed" toast still appears.

After installing or updating: restart the right process

Finish your running tasks, then fully quit and reopen Hermes Desktop (Cmd+Q on macOS; Quit/Exit elsewhere). Closing the window, reloading the desktop plugin, or running hermes gateway restart does not restart Desktop's separate hermes serve child for "This device". Plugin API routes mount at backend startup, not when the desktop UI reloads.

For a remote connection, restart the API-serving process on that host too. hermes gateway restart restarts the gateway service; a separately run hermes serve or hermes dashboard needs its own restart.

Open Mercury Relay in the Desktop sidebar after installation (enable its desktop half in Settings > Plugins if needed). The plugin-owned page shows this guidance even when its API is absent; this repository cannot change Hermes' core installation dialog.

A 404 with "Plugin not found" indicates the enablement gate: run hermes plugins enable mercury-relay in the backend's HERMES_HOME and restart the right process. A 404 with {"detail":"Not Found"} or Headless backend (hermes serve): web UI disabled — use `hermes dashboard` for the browser UI. on the plugin API path calls for a restart after installation. Headless backends can serve plugin APIs; a process started before installation has not mounted the route yet. Other 404s mean relay API unavailable, not proof of a missing installation. If it persists, check the active connection, installation, enablement, and backend logs. The roster shows operational only when the relay is actually connected.

Nothing happened?

Hermes Desktop is not installed on this computer, or the browser blocked the link. Install from the Hermes command line instead. This works the same on macOS, Linux, and Windows and targets the machine you run it on:

hermes plugins install unsupportedpastels/mercury-relay-plugin

Answer y when asked to enable the plugin, then follow the full-quit restart steps above. git must be on PATH for this command too.

Manual clone

Clone into plugins/mercury-relay under your Hermes home (~/.hermes on macOS and Linux, %LOCALAPPDATA%\hermes on Windows, or wherever HERMES_HOME points), then add mercury-relay to plugins.enabled in config.yaml, then follow the same restart steps. Full instructions are in the README.
